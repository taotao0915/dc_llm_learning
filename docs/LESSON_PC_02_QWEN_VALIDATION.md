日期：2026-10-03，北京时间。测试由助手执行，用户对新配置的亲自练习尚待反馈。

## 1. 先说结果

本机已下载 `qwen3:1.7b`，第二课默认改为这个模型，并设置 `think=False`。
6 个名字，每个重复 2 次，共 12 组两轮对话；12 次名字回答全部正确。
另用课堂原来的中文问候样例检查完整主循环，也得到了正确名字。

这是支持本课继续教学的小样本验证，不是模型在所有问题上的正确率，更不是永远不会出错的保证。
第一课的 `local-model-lab.py` 仍使用 DeepSeek；旧模型、原始失败记录均保留。

## 2. 为什么没有继续修改“记忆代码”

此前失败记录已经包含完整的 `user → assistant → user` 三条消息。
没有裁剪掉名字，也不是生成到上限才停止。所以不能把这次错误说成“程序忘记传历史”。

可以把程序理解成递送笔记的人，把模型理解成阅读笔记并回答的人：
笔记送到了，不等于读笔记的人一定答对。

本次保留消息列表的构造方式，改换模型和输出模式。效果改善支持使用这个新配置继续学习，
但没有单独隔离“模型变化”和“思考模式变化”的因果贡献，也没有确定旧配置失败的唯一底层原因。

## 3. 真正改动的两个关键位置

在 `scripts/chat-with-history.py` 顶部：

```python
MODEL = "qwen3:1.7b"
THINK = False
```

在发出的请求中：

```python
payload = {
    "model": MODEL,
    "messages": messages,
    "stream": True,
    "think": THINK,
    "keep_alive": "5m",
    "options": OPTIONS.copy(),
}
```

- `model`：选择本机已安装的哪一个模型，并不是修改 Python 解释器。
- `think=False`：请求 Qwen3 不生成独立的思考内容，直接生成正式回答。本课的短问答不必先等待一大段思考。
- 关闭思考生成并不等于零计算、不做推理或保证正确；它也不是仅把思考文字隐藏起来。
- `think` 与 `model` 同层，不放入 `options`。Python 中是 `False`，JSON 中是 `false`，序列化会自动转换。

上下文 4096、生成上限 1024、CPU 4 线程、temperature=0.6、seed=42 均维持原设置。
这些是本次课堂实测配置，不宣称是 Qwen3 的最优参数。未显式设置的参数仍可能随模型默认值不同而不同。

这 12 组也不是统计上充分独立、覆盖广泛的准确率评测。

## 6. 现在轮到你：先完成这一小步

1. 在 PyCharm 点停止，结束此前仍运行的旧脚本。仅保存文件不会替换已运行进程里的配置。
2. 打开 `scripts/chat-with-history.py`，右键 Run。不是第一课的 `local-model-lab.py`。
3. 确认开头写着 `本地模型 qwen3:1.7b`、`思考生成：关闭`。
4. 依次输入下面内容；每条都等待程序再次出现 `你：` 再输入下一条：

```text
我叫小林。请只回复：你好，小林。
我叫什么名字？请只回答名字。
/history
/clear
/history
/exit
```

第二轮应该显示“本次发送 3 条消息，包含 1 轮历史”。
名字回答应为“小林”，可能带句末标点；如果仍有错误，请保留输出和控制台显示的报告路径，不必反复运行直到碰巧答对。
`/clear` 后应看到空列表，但原来的 JSON 文件不会删除。

无需安装额外 Python 包，也无需填写运行参数。模型已下载，保持本机 Ollama 启动即可。
下载文件仍由 Ollama 的现有缓存管理，软件安装与缓存路径未迁移。

## 7. 这一课真正要记住的结论

模型的“记住名字”来自第二轮请求中再次附带第一轮文本，不是把名字训练进模型权重。
程序负责把信息送全；模型负责理解；两者要分开验证。

先能解释“为什么第二轮是 3 条消息”和“为什么清空后历史是空列表”，再进入下一课。
