# 已学基础概念与学习路线

本笔记于 2026-10-02 整理此前聊天讲解，供回顾；列出的后续课程不表示已经完成。

## 1. 什么是端侧大模型

端侧描述运行位置：让模型在用户的电脑、手机、汽车或其他本地设备上执行推理。
云端推理则把请求交给远程服务器执行。初次下载模型需要网络，文件准备好后，纯本地推理可以离线进行。

本地处理有助于让数据留在设备上，也避免了按次调用云端模型 API 的费用，但仍消耗硬件、电量和开发维护成本。
隐私是否得到保障，还取决于应用是否上传日志、原文或其他数据；运行速度也受设备性能制约。

端侧设备需要在模型效果、内存、速度、功耗和散热之间做取舍。

## 2. 训练、推理和应用开发

训练通过数据调整模型参数；推理使用已有参数为新输入生成结果。
我们目前学习的是选择已有模型、运行推理、接入程序和测量性能。
以后可继续学习量化、格式转换、硬件加速和手机部署。

完整开发流程通常包括：

需求 → 模型选择 → 获得兼容的模型文件 → 推理引擎运行 → 程序调用 → 测试效果和资源占用 → 优化与部署。

已有可用量化文件时，可以直接使用，不必每次自己转换和量化。

## 3. 参数量为什么影响内存

`B` 表示十亿；`7B` 大约是 70 亿参数。
权重原始数据量可以用“参数数目 × 每参数字节数”估算：

| 表示方式 | 每参数理想字节数 | 7B 权重粗估（十进制） |
|---|---:|---:|
| FP32 | 4 | 28GB |
| FP16 / BF16 | 2 | 14GB |
| INT8 | 1 | 7GB |
| INT4 | 0.5 | 3.5GB |

这些不是运行内存的完整预算。量化系数、部分高精度张量、缓存和计算缓冲区都会增加开销。
GB 与 GiB 的单位也不同：1GB = 10^9 字节，1GiB = 2^30 字节。

总运行内存大致由权重、KV Cache、计算临时空间和推理程序开销组成，还需给操作系统和其他应用留出空间。
磁盘空间够存模型，不代表内存足够加载，也不代表运行速度令人满意。

## 4. 量化

量化用更少位数近似表示参数，降低权重占用；通常需要缩放等信息，并不是简单删除小数位。
我们已认识 FP32、FP16/BF16、INT8、INT4 等表示方式，以及当前模型使用的 Q4_K_M 混合量化。

位数更低通常更省空间，但效果可能下降，速度是否提高取决于硬件和实现。
第一次实验采用已有 Q4_K_M 模型，自己执行量化尚未学习。

## 5. Token、上下文和生成

文字先由分词器转换为 token ID，再送入模型计算。
模型依据已有上下文预测下一个 token，并逐步扩展输出。
Token 可能是一个字、一个词、词的一部分或标点，不能当成汉字数。

上下文窗口容纳本次处理的输入、历史和新生成内容。
设置的输出上限则限制这次最多生成多少 token。二者不是同一个参数。

常见生成阶段：

- Prefill：处理输入问题和已有上下文。
- Decode：逐个生成后续 token。

首次看到内容的时间还可能包含模型加载、排队和传输等开销。
思考模型可能先生成思考内容，之后才开始正式回答，所以首次生成与首次回答可能相差很久。

## 6. KV Cache

常见 Transformer 推理会缓存此前 token 的部分注意力计算结果，即 Key 和 Value。
这样生成新 token 时可以复用前面的结果，不必重新计算所有历史 token 的相应部分。

KV Cache 是推理缓存，不等于把聊天永久保存，也不等于修改模型权重。
其大小与模型结构、精度、缓存长度和并发等有关；常规全注意力模型的缓存通常随序列变长而增加。
初学时以 2048 上下文建立基准，之后再观察增加上下文的影响。

## 7. 硬件与推理工具

CPU 是通用处理器；GPU 擅长许多并行计算；NPU 面向特定神经网络计算。
实际加速取决于模型、算子、驱动和推理后端是否适配，不能仅根据有无 GPU/NPU 判断。

此前介绍过的路线包括：

- llama.cpp + GGUF：学习模型文件、量化、CPU/GPU 推理和底层参数。
- Ollama：管理和运行本地模型，提供命令行和本地 HTTP 接口；本次已复用它跑通实验。
- ONNX Runtime：另一类跨平台推理路线，需考虑模型与执行后端的兼容性。
- 手机端框架与厂商 SDK：后续涉及 ARM64、JNI、CMake、线程、内存、发热和模型文件管理。

目前没有在本次课程中验证核显或 NPU 加速，也没有从零训练模型。

## 9. 已学实验结论

运行链路成功、输出完整、回答正确，是三个独立检查项。
当前小模型曾把“端侧”混淆成“端到端”，说明本地部署并不保证答案正确。
用户已回答推理需要时间；进一步需要理解思考生成和正式答案生成都会消耗时间及输出预算。
