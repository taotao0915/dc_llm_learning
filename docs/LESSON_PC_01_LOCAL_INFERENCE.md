# 电脑端第 1 课：让本机模型真正回答一次问题

这一课只掌握一条链路：输入问题 → 本机推理工具 → 模型 → 回答。

## 1. 这次使用什么

本机已经安装 Python 3.12.8、Ollama 0.34.1，并已下载
`deepseek-r1:1.5b`，所以本课复用现有环境。先前推荐的
Qwen3-1.7B 留给后续模型对比；这次没有新增模型下载。

| 名称 | 类比 | 实际作用 |
|---|---|---|
| 模型文件 | 保存了所学内容的一本大书 | 保存权重、词表等数据 |
| Ollama | 负责运行模型的工具 | 管理模型、启动推理、提供本地接口 |
| Python 练习脚本 | 负责提问和记录的小助手 | 发送问题、接收输出、记录耗时 |

模型不能自己运行，需要推理程序读取它并执行计算。Python 在这个实验中负责调用接口，主要的模型计算由本地推理程序完成。

已有模型采用 GGUF 格式和 Q4_K_M 量化，下载文件总量约 1.12GB（十进制）。
Q4_K_M 是常见的混合量化方案，不能理解为每个参数都严格只占 4 位。
标签中的 `1.5b` 是模型名称的一部分；本机元数据记录的参数总数为
1,777,088,000，工具四舍五入显示为 1.8B。名称和元数据统计口径可能不同。

## 2. 打开 PowerShell，进入练习目录

在 Windows 开始菜单搜索 PowerShell，打开后输入：

```powershell
Set-Location 'F:\Software\JetBrains\PyCharm\PycharmProjects\20260624\dc_llm_learning'
```

`Set-Location` 表示切换当前工作目录。下面的脚本路径都以这个目录为起点。

先看已经下载的模型：

```powershell
ollama list
```

看到 `deepseek-r1:1.5b` 表示模型文件在本机。

再看当前加载的模型：

```powershell
ollama ps
```

这两条命令回答的是不同的问题：`list` 看磁盘上有什么，`ps` 看当前内存中加载了什么。
因此，`list` 有模型、`ps` 为空是正常情况。

如果 PowerShell 提示找不到 `ollama`，可使用本机检测到的完整路径：

```powershell
& 'E:\Software\Ollama\ollama.exe' list
```

`&` 表示执行引号里的程序路径。

## 3. 运行练习脚本

```powershell
python scripts/local-model-lab.py --max-tokens 512
```

如果服务尚未启动，先从开始菜单启动 Ollama，待 `ollama list` 能正常使用后再运行。

脚本默认问题是：

> 请用一句简短的中文解释什么是端侧大模型。

模型的回答属于实验输出，需要核对正确性；不能因为是在本地生成，就认为它一定正确。
一个准确的参考解释是：端侧大模型是在手机、电脑等本地设备上执行推理的模型，可以用于本地问答等任务。

你会依次看到：

1. 正在请求本机模型。
2. 模型正在生成思考内容。
3. 模型的正式答案（如果在输出预算内生成了答案）。
4. 首次输出等待时间、生成速度、总耗时和结束原因。

这份脚本使用 Python 标准库，不需要 `pip install`。它连接固定地址
`http://127.0.0.1:11434`：`127.0.0.1` 表示本机，`11434` 是服务端口。
本课的问题发送给本机推理服务，没有调用云端模型 API。
这个事实不等于整台电脑没有其他联网行为，例如 Ollama 应用自身可能检查更新。

## 4. 看懂这几个设置

脚本内的核心设置是：

```python
options = {
    "num_ctx": 2048,
    "num_thread": 4,
    "num_gpu": 0,
    "num_predict": 512,
    "temperature": 0.6,
    "seed": 42,
}
```

上面展示的是命令传入 `--max-tokens 512` 时的配置；不传该参数时脚本默认为 256。

- `num_ctx`：上下文窗口预算。输入、对话历史和新生成内容需要放进这个窗口。
- `num_thread`：CPU 推理线程数。本机 4 个物理核心，先以 4 线程建立基准。
- `num_gpu`：本课设为 0，固定使用 CPU。
- `num_predict`：本次最多生成多少 token。对当前思考模型，思考内容也消耗这个预算。
- `temperature`：采样设置，影响输出随机性；本课固定它，先观察其他变量。
- `seed`：固定随机种子，有助于复现实验，但不保证跨硬件、版本或运行环境完全一致。

Token 不等于汉字数：一个汉字、词片段或标点可能对应一个或多个 token。
所以 `512 token` 不能直接解释成 `512 个汉字`。

## 5. 看懂结果，不混淆几个时间

| 指标 | 意义 |
|---|---|
| 首个生成片段 | 从发送请求到第一次收到非空思考或回答内容 |
| 正式答案首片 | 从发送请求到第一次收到非空正式回答 |
| 加载耗时 | 服务报告的模型准备/加载时间 |
| Prefill 耗时 | 服务报告的输入处理时间，可能受缓存影响 |
| Decode 耗时 | 服务报告的输出 token 生成时间 |
| 客户端总耗时 | 从请求开始到收到完整响应结束 |

本脚本测得的是客户端收到片段的时间，不是底层计算核精确产生第一个 token 的时间。
一个网络片段可能包含多个字符或 token。

生成速度的计算：

```text
生成速度 = 生成 token 总数 ÷ Decode 秒数
```

这里包含模型生成的思考内容，所以不等于正式回答在屏幕上显示汉字的速度。
也不能用 `生成 token 总数 ÷ 整个请求总耗时` 替代该指标，两者含义不同。

注意结束原因：

- `stop`：服务报告正常停止，还应检查回答是否符合问题。
- `length`：碰到输出长度上限，答案可能没写完，甚至尚未开始。

请求成功返回不等于回答已经完成。接口是否正常、内容是否完整、回答是否正确，是三个不同的检查项。

## 6. 本机实际发生了什么

2026 年 10 月 1 日，在 i7-1165G7、约 32GB 内存、Windows 11 的本机运行两次。
固定为 CPU、4 线程、2048 上下文，问题均为“请用一句简短的中文解释什么是端侧大模型。”

| 观察项 | 第一次 | 第二次 |
|---|---:|---:|
| 输出上限 | 256 token | 512 token |
| 请求前模型已加载 | 否 | 是 |
| 服务报告加载时间 | 6.080 秒 | 0.023 秒 |
| 首个生成片段 | 6.918 秒 | 0.352 秒 |
| 正式回答首片 | 没有收到 | 47.341 秒 |
| 生成数量（含思考） | 256 token | 467 token |
| Decode 速度 | 9.08 token/s | 8.80 token/s |
| 请求总耗时 | 34.858 秒 | 53.222 秒 |
| 结束原因 | length | stop |

第一次输出预算耗尽时仍在生成思考内容；第二次增加预算后，才得到正式答案。
第二次等待首个生成片段的时间更短，也受到模型已经加载和输入缓存的影响。
它的总耗时更长，主要因为生成的 token 更多。这两次不构成严格的冷/热性能对照，也不是线程性能对照。
每种条件只有一次，不能把这些数值当成设备固定速度。

第二次模型声称“端侧大模型通常指端到端的大模型”，这是错误的。
端侧描述的是模型在哪里执行；端到端描述的是从输入到输出的处理/学习方式。两者是不同维度。
本次验证了推理链路能工作，但这道知识问答没有通过质量检查。

第二次生成结束后，Windows 查询到 `llama-server` 进程工作集约 1188.8 MiB，约 1.16 GiB。
这是一个时刻该进程的驻留内存，不含其他 Ollama 进程，也不是峰值。
服务报告的加载模型 `size` 约 1.24GB 是另一个口径，不能混为一谈。

完整机器可读记录保存在工作区 `output/local-model-lab/first-run.json` 和 `second-run.json`。

## 7. 自己做两个小实验

先用短问题运行一次：

```powershell
python scripts/local-model-lab.py --prompt '1加1等于几？' --max-tokens 512
```

再用相同的问题比较 4 线程和 8 线程：

```powershell
python scripts/local-model-lab.py --prompt '1加1等于几？' --threads 4 --max-tokens 512
python scripts/local-model-lab.py --prompt '1加1等于几？' --threads 8 --max-tokens 512
```

先理解指标即可。要正式比较线程性能，需要固定模型、问题、输出预算和其他参数，预热后分别重复多次，再考虑散热、后台负载、缓存及输出长度差异。
线程更多不保证更快，4 核 8 线程也不等于 8 个完整物理核心。

保存一次记录：

```powershell
python scripts/local-model-lab.py --max-tokens 512 --report output/local-model-lab/my-run.json
```

报告包含问题、正式答案、参数和耗时，不保存思考正文。
`loaded_models_after_request` 中的 `size` 是服务报告的加载模型大小，不能当成 Windows 进程峰值内存；`size_vram` 为 0 与本课 CPU 设置对应。

## 8. 实验后释放模型内存

脚本使用 `keep_alive: "5m"`，方便短时间内再次测试。也可以主动卸载：

```powershell
ollama stop deepseek-r1:1.5b
```

这里的 `stop` 是卸载内存中的模型，不删除磁盘上的模型文件。
